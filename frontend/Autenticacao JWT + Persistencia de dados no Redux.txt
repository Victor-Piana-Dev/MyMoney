Criação da autenticação JWT no front-end:

Passo 1: Alterar a função login no service.module.js para salvar o token recebido da API do backend no localStorage:

localStorage.setItem('token', response.data.token);


Passo 2: Criar um Hook para Recuperar o Token e Verificar a Autenticação, no caso o useAuth.jsx. Esse hook pode ser utilizado em qualquer componente para verificar a presença do JWT.


Passo 3: Criar um Componente de Proteção de Rota. O próximo passo é garantir que algumas rotas sejam protegidas e acessíveis apenas para usuários autenticados. Crie um componente ProtectedRoute que verificará se o usuário está autenticado antes de permitir o acesso a páginas restritas.


Passo 4: Redirecionar após o Login e Logout. Ajustar o código para que, após o login bem-sucedido, o usuário seja redirecionado para uma página protegida (por exemplo, Dashboard). Isso foi feito no componente Home.jsx usando o useNavigate, adicionando o navigate('/dashboard'); Para o logout, você pode criar uma função que remova o token do localStorage e redirecione o usuário para a página de login, exemplo foi feito no arquivo Menu.jsx: 

function logout() {
    localStorage.removeItem('token');
    window.location.href = '/'; // Redireciona para a página de login
}


Passo 5: Exigir Autenticação para Rotas Protegidas, Agora, você pode usar o ProtectedRoute para proteger as rotas que exigem autenticação. Atualize a definição das rotas no arquivo routes.jsx para usar o ProtectedRoute.


Passo 6: Finalizando a Proteção nas Requisições, Para garantir que as requisições ao backend sejam feitas apenas com o token JWT (se o usuário estiver autenticado), você pode configurar o axios para enviar o token em cada requisição. Ou seja precisamos enviar o token novamente para o backend para que seja usado na função checkToken.



A razão pela qual você ainda precisa enviar o token para o backend e usar a função checkToken no backend é que o token serve para autenticar o usuário em requisições subsequentes, garantindo que ele tem permissão para acessar recursos protegidos.

Aqui está um detalhamento de por que isso é necessário:

1. Verificação do Token no Front-End:
Quando você armazena o token no localStorage no front-end, você já está verificando se o token existe, o que impede que o usuário acesse rotas protegidas sem um token válido.
Porém, isso é apenas uma verificação local para saber se o usuário está autenticado e se ele pode navegar pelas rotas protegidas.
O ProtectedRoute apenas impede que o usuário acesse a página diretamente no front-end sem estar autenticado. No entanto, isso não garante que a requisição ao backend seja autenticada, pois a API não tem conhecimento do token armazenado no navegador (localStorage).


2. Envio do Token ao Backend:
Quando o front-end faz uma requisição (por exemplo, para acessar dados, criar ou editar algo no backend), ele precisa enviar o token ao backend.
O backend precisa do token para verificar se a requisição está sendo feita por um usuário autenticado.


3. Validação no Backend:
A função checkToken no backend é responsável por validar se o token que o front-end está enviando na requisição é válido.
Embora o front-end tenha verificado se o token existe e o tenha armazenado no localStorage, o backend não tem acesso a esse estado local do front-end. Portanto, ele não pode confiar somente no front-end.
O token enviado pelo front-end nas requisições precisa ser validado no backend para garantir que o token não tenha sido manipulado ou expirado, e que ele corresponda ao que foi gerado no momento do login.


4. Processo Completo:
Front-End: O front-end verifica se o token está presente e, se for o caso, permite o acesso a rotas protegidas.
Requisição ao Backend: Quando o front-end faz uma requisição ao backend, ele deve enviar o token no header Authorization como Bearer <token>.
Backend: O backend recebe esse token e usa a função checkToken para verificar se ele é válido, garantindo que a requisição está sendo feita por um usuário autenticado.


5. Resumo:
No front-end: Você usa o token para impedir que rotas protegidas sejam acessadas sem autorização. Porém, ao fazer uma requisição ao backend, o token precisa ser enviado para que o backend possa validar se o usuário tem permissão para acessar os dados.
No backend: O backend verifica a validade do token recebido nas requisições. Se o token for inválido ou estiver ausente, o backend responde com um erro de autorização (exemplo: 401 ou 400).
Portanto, mesmo que você esteja usando o useAuth no front-end para proteger rotas, o backend precisa validar o token em cada requisição para garantir a segurança do sistema.
